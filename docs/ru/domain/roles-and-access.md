# Роли и доступ

## Матрица ролей

| Возможность | instance_admin | org_admin | org_member |
| ----------- | -------------- | --------- | ---------- |
| Настройки инстанса, воркеры, тарифы | Да | Нет | Нет |
| Impersonate пользователей | Да (не во время impersonate) | Нет | Нет |
| Просмотр всех org / всех задач | Да | Нет | Нет |
| Управление пользователями org, статистика | Нет | Да | Нет |
| CRUD навыков org | Нет | Да | Каталог только для чтения |
| Кошелёк / тариф (самообслуживание) | Нет | Смена на доступный тариф | Нет |
| Собственные артефакты + общие | Если состоит в org | Да | Да |
| Создание задач | Если состоит в org | Да | Да |
| Жёсткое удаление артефактов org | Нет | Да | Нет (удаление своего summary — да) |
| API-токены | Да (без org) | Если tariff.api_enabled | Если tariff.api_enabled |

`instance_admin` создаётся один раз на `/setup`. Обычно у него **нет членства в org** — домашняя страница UI по умолчанию ведёт в Instance, пока он не присоединится к org вручную (через signup это не поддерживается).

## Один пользователь — одна org

`memberships.user_id` уникален. Пользователь принадлежит ровно нулю или одной организации. При signup всегда создаётся новая персональная org.

## Видимость объектов

Для `audio`, `transcript`, `summary`:

| Кто смотрит | Видит |
| ----------- | ----- |
| Владелец | Свои объекты (фильтр скрытых — опционально) |
| org admin | Все объекты в org |
| org member | Свои + объекты, расшаренные **ему** |
| instance admin | Все (при запросе от имени админа) |

Реализация: `can_read_object()` в `app/services/access.py`.

### Скрытие vs удаление

| Действие | Кто | Эффект |
| -------- | --- | ------ |
| **Hide** | Только владелец | Строка в `hidden_items` — объект исключается из списков по умолчанию |
| **Delete (wipe)** | org admin | Жёсткое удаление артефакта и зависимостей через `artifacts.py` |
| **Delete summary** | Владелец или org admin | Жёсткое удаление одного summary |

Скрытые объекты — per-user; другие участники org по-прежнему видят объект, если у них есть доступ.

## Шаринг

`POST /shares` — владелец делится `audio`, `transcript`, `summary` или персональным `skill` с участниками org (`to_user_ids`).

- Цель шаринга должна быть в той же org
- Получатели видят `share_kind: incoming`, email в `shared_by`
- Владелец видит список `shared_with`
- Любая сторона может вызвать `DELETE /shares/{share_id}`

Навыки с `scope=self` можно шарить; org/base навыки используют видимость каталога вместо шаринга.

## Видимость задач

| Роль | Видимые задачи |
| ---- | -------------- |
| instance_admin | Все; опциональные фильтры `?org_id=` и `?user_id=` |
| org_admin | Все задачи в org; опциональный `?user_id=` |
| org_member | Собственные задачи в org |

## Защита последнего org admin

Операции, которые оставят ноль активных org admin, отклоняются с кодом `last_org_admin` (HTTP 409):

- Понижение/отключение единственного админа
- Offboarding без замены

## Режимы блокировки по паролю

| Условие | Разрешённые endpoints |
| ------- | --------------------- |
| `must_change_password` | `/me`, PATCH `/me`, смена пароля, logout, stop impersonate |
| Истёк TTL пароля (настройка org) | То же (для пользователей, не являющихся instance admin) |

instance admin обходит блокировку по TTL пароля для API-паттернов, связанных с админскими workflow.

## Маршрут по умолчанию

Пользователи могут задать `default_route` через PATCH `/me`: `library`, `skills`, `org`, `stats`, `tasks`, `instance` — только маршруты, разрешённые для их роли. См. `web/src/routes.ts`.
